# API 路由与认证

> 上级文档：`AGENTS.md`。新增/修改 `/api/*` 路由前必读。

| 路由 | 方法 | 认证 | 说明 |
|------|------|------|------|
| `/v1/*`, `/v1beta/*`, `/raw/*` | 全部 | 虚拟 key（`vk-` 前缀，DB 加密比对） | 代理入口：虚拟 key 校验 → vk model allowlist → model 路由 → 上游 key 故障转移链 → 纯透传 + usage 解析写库（`/raw/*` 先剥离前缀再按内层 path 走同一套逻辑，见 `gateway.md`） |
| `POST /api/auth/login` | POST | 原始 API key（响应 `Set-Cookie` 下发 httpOnly 会话 cookie `tt_session`；body 同时返回明文 token 供脚本 `X-API-Key` 使用）（DB 优先，env 兜底且**仅强 key**）+ 可选第二因素（TOTP 动态码或 recovery code） | 登录换会话 token（唯一换取入口；**限流先于读 body**，64KB 流式 body 上限（content-length 与 chunked 双覆盖，超限 413）；key 无效/缺 TOTP/TOTP 错误统一 401 同文案，无 oracle） |
| `GET/POST /api/auth/setup` | GET/POST | 无（fail-open 闸门自校验；POST 成功同样 `Set-Cookie` 下发会话 cookie） | 首次设置向导：GET 探测 `{setupRequired, authDisabled}`（`LOCAL_ADMIN_BYPASS` 生效时 `authDisabled: true` 且 `setupRequired` 恒 false）；POST 设置初始 admin key + 返回会话 token（仅当 DB 无 key AND env 无 key，限流先于读 body + 64KB body 上限 + 事务 re-check；弱 key 仅提示、允许使用） |
| `POST /api/auth/logout` | POST | 无（不验签：cookie 可能已过期，清 cookie 必须可达；验签层已排除） | 登出：过期 `Set-Cookie` 吊销浏览器登录态；全局吊销走 `/api/admin/auth/sessions` epoch+1 |
| `GET /api/auth/session` | GET | 会话 token | 登录态探测（httpOnly cookie 前端 JS 读不到）：200 = 已登录，401 = 未登录（验签层顺带清失效 cookie）；ApiKeyGate 首帧数据源 |
| `/api/dashboard` | GET | 会话 token（`X-API-Key` header） | 聚合统计（total + today + yesterday + daily + models + 365 天 heatmap + 24h 分布） |
| `GET /api/cli` | GET | **无（公开）** | 公开用量快照：`generatedAt`（ISO 8601 UTC，快照生成时刻）+ `summary`（全时段累计）与 `today`（当日，日界与 `/api/dashboard` 的 `today` 一致）**字段集完全相同**：`totalInput`/`totalInputCached`/`totalInputUncached`/`totalCacheWrite`/`totalOutput`/`requests`/`cacheHitRate`（0~1），today 额外带 `date`；**不含任何 cost 字段**（成本可通过 dashboard 看），不含 model/provider 名、逐日曲线、`lastActiveAt`。**唯一参数 `tzOffset`**（`getTimezoneOffset` 语义，严格十进制整数，-720~720，缺省 0 = UTC，非法值 400），`provider`/`agent`/`range` 等参数一律忽略（过滤会构成名单枚举 oracle）。进程内 60s 快照做全局限流：同 tzOffset 的 TTL 内请求返回同一份 JSON 且不读库（多实例各自一份），快照最多 32 条 LRU + 每 60s 全局刷新预算 8 次（防用 tzOffset 放大查询；预算耗尽且无缓存时 429 + `Retry-After: 60`）；刷新失败或预算耗尽但该时区仍有快照时退回旧快照。所有响应统一带 `Cache-Control: no-store` |

- **认证架构（多层防漏）**：验签 proxy（第一层，`src/server/verify-session.ts` Hono 中间件包裹 `src/server/proxy.ts`，WebCrypto 验 HMAC 签名 + exp；排除清单 `VERIFY_EXCLUDED` = `auth/login`、`auth/setup`、`auth/logout`、`cli`、`device/pair/start`、`device/pair/poll`、`device/plan`、`device/report`（精确匹配））→ 路由内 `withAuth`（第二层，epoch 检查 + DB key 指纹校验）/ `withDeviceAuth`（device token 层，见下）→ vitest 静态扫描测试（第三层，`src/lib/auth/guard-scan.test.ts`：`exempt` 白名单 login/setup/logout/cli/pair-start/pair-poll + `deviceAuth` 集合 plan/report + `device/**` 无漏网断言）→ `AGENTS.md` 约定（第四层）
- **device token 层（relay）**：`src/lib/auth/device-guard.ts` 的 `withDeviceAuth`，与 `withAuth` **平行不复用**（两套凭证）——只接受 `Authorization: Bearer dt-…`（不接受 query），**每次直读 DB**（不进查询缓存，revoke 立即生效），不读 `GATEWAY_SECRET`、不解会话 token、不校 `token_epoch`；`last_seen_at` fire-and-forget 更新。中心只存 `sha256(token)`（比 `ingest_tokens` 更严：它能换真实 upstream key），明文只在 `pair/poll` 成功时下发一次。`/api/device/{plan,report}` 必须被它包裹；`/api/device/pair/lookup` 用 `withAuth`（会话态）
- **本地免密码直通（`LOCAL_ADMIN_BYPASS=1`）**：`src/lib/auth/local-bypass.ts` 的 `canBypassAuth()` 同时要求 env 开启 **且** **Host ∧ socket 对端双条件**：Host 必须 loopback（localhost / 127.x / ::1），且取得到对端时对端（内部 header `x-internal-remote-addr`，由 `src/server/client-addr.ts` 从 `IncomingMessage.socket.remoteAddress` 无条件写入，客户端同名 header 被覆盖且不转发 upstream）也必须 loopback；对端取不到（next dev 单进程 / 单测直调）退化为纯 Host 判定。为什么 AND：只看对端会让同机反代回连 127.0.0.1 时把公网流量免密放行，只看 Host 则可被任意伪造。生效时 proxy 与 `withAuth` 双双跳过认证，setup GET 返回 `authDisabled: true`，前端 `ApiKeyGate` 直接进入 admin（logout / 401 跳转均 no-op）。**仅 `docker-compose.local.yml` 设置该 env（端口绑定 127.0.0.1），VPS / 对外部署 / 反代之后严禁开启**；docker 桥网络下本机请求对端是网桥网关（非 loopback）→ 不生效
- **⚠️ breaking change**：除 login、setup、logout 与接口表登记的公开只读例外 `/api/cli` 外，`/api/*` 只接受会话 token（HMAC-SHA256 签名，GATEWAY_SECRET 派生密钥），**原始 API key 不能直接调 API**。脚本/curl 必须先 `POST /api/auth/login`（body `{apiKey, totpCode?}`）换 token，再带 `X-API-Key: <token>` 调用
- **新增 /api 路由默认必须用 `withAuth` 包裹**（`src/lib/auth/guard.ts`），否则静态扫描测试失败。公开例外需同时改 `guard-scan.test.ts` 的 `exempt` **和** `src/server/verify-session.ts` 的 `VERIFY_EXCLUDED`（只改前者会在验签层被拦成 401），并在本文件接口表写明公开理由与返回字段。**route 文件放 `src/routes/**/route.ts`**（与 URL 路径镜像，`src/app` 只剩静态导出页面）；新增/移动后 `npm run dev` / `npm run build` 自动重跑 `scripts/gen-routes.mjs` 生成 `src/server/routes.generated.ts`，手改生成文件无效。route 文件里的 `runtime`/`dynamic` 导出对 Hono 无效（历史保留）；`from "next/server"` 由别名指到 `src/server/next-shim.ts`（shim 缺 API 时 tsc 不报、运行时才炸，扩 API 面先改 shim）
- **首次设置向导（唯一 fail-open 入口）**：`src/lib/auth/setup.ts` 的 `canRunSetup()` ⟺ DB 无 `admin_api_key` AND env **未配置任何 key**（用 `getEnvAdminKeysConfigured()`，**不过滤强度**）；`runSetup()` 事务内 re-check + 写 key + epoch+1 + 签发 token；verify-session 排除清单已含 `auth/setup`；独立限流 bucket、审计 `setup_admin_key`
- **登录 key 强度（仅提示）**：个人/家庭部署允许弱 key，`src/lib/login-key-strength.ts` 的 `getLoginKeyStrength()` 只驱动前端提示；`runSetup`、`PATCH /api/admin/auth/api-key` 和 env 登录均不拒绝弱 key。env 是否已配置统一由 `getEnvAdminKeysConfigured()` 判定，弱 key 也算已配置，因此 `canRunSetup()` 仍为 false，不会被当成「未配置」重新打开向导（`src/lib/auth/setup.test.ts` + `src/routes/api/auth/{login,setup}/route.test.ts` 覆盖）
- **认证端点请求体**：`src/lib/auth/request-body.ts` 的 `readJsonBodyLimited()`（64KB 上限，content-length 声明超限直接拒 + chunked 边读边累计；非对象 JSON 归一 `{}`）。**限流必须先于读 body 执行** —— 缺 key / 坏 JSON / 超大 body 都计入限流桶，不得绕过
- **会话 token**：payload 含 `exp + epoch + keyId`；`keyId` = 登录 key 的 HMAC 指纹（`keyFingerprint`，GATEWAY_SECRET 参与，防持有 token 者离线字典攻击）；**静默轮换兼容**：HMAC 化之前签发的存量 token 装的是老格式裸 sha256 指纹（`legacyKeyFingerprint`），`resolveActiveKeyId` 命中即放行并**立即换发新格式 token**（`X-Session-Token` / `Set-Cookie`）——存量 token 用一次就升级，最迟 `exp` 后消失，兼容窗口过后可删 guard.ts 的 legacy 分支；TTL 由 `resolveSessionTtlMs()` 决定（settings `session_token_ttl_hours` > env `SESSION_TOKEN_TTL_HOURS` > 默认 24h，只影响新签发 token）；认证通过且剩余不足一半时滑动续期——header 认证的脚本走 `X-Session-Token` 响应头，cookie 认证的浏览器走 `Set-Cookie` 续上 `tt_session`；两者**互斥**（续期 token 不能同时下发两种载体，否则同源 JS 可从响应头读走本该 httpOnly 的续期 token）
- **浏览器登录态 = httpOnly Cookie**：`tt_session`（`src/lib/auth/session-cookie.ts`），`HttpOnly; SameSite=Lax; Path=/; Max-Age=<TTL>`；`Secure` 仅 https / localhost（安全上下文）时加，纯 http+LAN IP 部署不设 Secure（否则浏览器拒收导致登录死循环）。⚠️ 不设 Secure = 会话 cookie 走明文 HTTP，内网中间人可截获，仅限明确接受该风险的受信网络使用，公网部署务必 HTTPS。前端 JS 读不到 token，`apiFetch` 同源请求浏览器自动携带；关浏览器重开仍在（直至过期/吊销/登出）。proxy 与 withAuth 认证来源均 **header `X-API-Key` 优先，其次 cookie**；401 时仅当请求实际凭 cookie 认证才下发过期 `Set-Cookie` 清 cookie（header 优先不能误清）。CSRF：state-changing 接口均为 POST/PUT/PATCH/DELETE + `SameSite=Lax` 跨站不携带，已足够
- **key 生命周期**：修改登录 key（settings 表 `admin_api_key`）时 `token_epoch + 1` → 所有已签发 token 立即 401，env `ADMIN_API_KEY` 旧 key 立即失效（DB 有 key 时 env 不再被检查）
- **防锁死恢复**：settings 表无 `admin_api_key` 时回退 env `ADMIN_API_KEY` 兜底；如忘记 key 导致无法登录，删除 `settings` 表中的 `admin_api_key` 行即可恢复（sqlite3 CLI 操作）
- **settings 读写必须包 `withSkipCache()`**（`src/lib/auth/settings.ts`）：查询缓存 TTL 10s，否则改 key/epoch+1/解绑 TOTP 后旧凭证最长残留 10s
- **限流 IP 来源**：`src/lib/net/client-ip.ts` 的 `getRateLimitKey()` 统一取值 —— `TRUSTED_PROXY=true` 时取 `x-real-ip`（回退 XFF 末位，反代追加的真实 IP）；默认 false 时忽略全部客户端可控头，退化为全局桶（不可伪造，防 XFF 绕过；代价是攻击者可阻塞登录窗口，但无法爆破）。`extractClientInfo`（审计展示用）只取可信 IP，原始 XFF 存 `xffRaw` 仅供排查
- **页面认证**：`/`、`/admin` 由客户端 `ApiKeyGate` 处理，无 proxy；首帧 `apiSetup()`（setup 探测/本地直通）→ `checkSession()`（`GET /api/auth/session` 探 httpOnly cookie 有效性，裸 fetch 不触发 401 拦截）；登录后 401 拦截（`notifyUnauthorized` 回登录页）+ 本地两步登录：先 key 后 TOTP，第二步触网，未启用 TOTP 留空即可；全局 fetch 走 `src/lib/client/api-client.ts` 的 `apiFetch`（无任何 token 存储逻辑，cookie 浏览器自动携带）
- **TOTP**：RFC 6238 自实现（`src/lib/auth/totp.ts`，30s 窗口 ±1 容差）；admin + dashboard 共用一次登录；暴力防护 `src/lib/auth/totp-lock.ts`（连续 5 次失败锁 15min，之后每 5 次翻倍封顶 24h，计数持久化 settings 表防重启清零，成功清零；锁定期间本人也无法登录，sqlite3 删除 `totp_locked_until` 行恢复；login 与 admin TOTP 绑定/解绑/改 key 共用）
- **换绑**：已启用 TOTP 时生成新 pending 必须带 `currentCode`（旧 secret 验证，失败 `recordTotpFailure()` 计入锁定计数）；换绑成功 `bumpTokenEpoch()` 吊销全部会话（首次启用**不**吊销，保持登录立即展示恢复码）；解绑成功同步 `clearRecoveryCodes()`。⚠️ **前端时序**：换绑成功后 SecuritySettings **不得**再发任何 API 请求（token 已失效会 401 提前踢人，recovery codes 弹窗来不及展示），应仅展示弹窗，关闭弹窗时提示会话已吊销并调 `notifyUnauthorized()` 跳登录
- **Recovery codes 原子消费**（`src/lib/auth/recovery-codes.ts`）：`verifyRecoveryCode()` 在 `BEGIN IMMEDIATE` 事务内「重读 → 比对 → 标记 → 写回」，并发复用同一码只有一次返回 true（无双花窗口）
- **Recovery codes**（`src/lib/auth/recovery-codes.ts`）：格式 `XXXX-XXXX-XXXX-XXXX`，字符集排除 `0/O/I/1`；每次生成 4 个一次性码，存储**只存 SHA-256 哈希 + used 标记**（JSON），明文仅在生成成功响应返回一次；登录分流 `classifySecondFactorInput`（6 位纯数字 → TOTP；归一化 16 位 → recovery；其余 → TOTP 分支必然失败）；recovery 验证**绕过 TOTP 锁定**、失败**不计入** `totp_fail_count`（走 login 全局限流桶）、成功清除锁定计数 + 写 `recovery_code_login_reminder='1'`；login 响应带 `viaRecoveryCode: true`，ApiKeyGate 弹 alert，Security 面板显示黄色横幅（「我已检查」DELETE reminder 路由清除）；重新生成（POST recovery-codes）需当前 TOTP 验证，**不**吊销会话；GET 返回 `{remaining, reminder, exists}`（exists 区分「从未生成」黄横幅与「全部用完」红横幅）
