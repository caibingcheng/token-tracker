# 数据库架构（Drizzle ORM）

> 上级文档：`AGENTS.md`。改 schema / 加表加列 / 写迁移前必读。

- **Schema**：`src/lib/db/schema-sqlite.ts`（sqlite-core）
- **连接配置**：`src/lib/db/index.ts`，懒加载初始化
- **关键配置**：better-sqlite3 **13.x（N-API 版，要求 Node >= 22）**，文本模式存储时间戳（ISO 格式）
  - ⚠️ 为什么必须是 13.x：11.x/12.x 是传统 NAN/V8 绑定，`Statement::~Statement` 走 `node::RemoveEnvironmentCleanupHook`；Node 24 在 worker/子进程退出时环境已先行拆除，退出期 GC 销毁 Statement 会命中 `Assertion failed: (env) != nullptr` 直接 abort（`npm test` 表现为 87-88/89 文件后 worker native abort）。13.x 换用 node-addon-api（二进制里已无 `*EnvironmentCleanupHook`，改用 `napi_*_env_cleanup_hook`），该崩溃路径消失；Drizzle 驱动（`drizzle-orm/better-sqlite3`）API 未变，迁移与查询无需改动
- **自动初始化**：`initDatabase()` 在首次 API 调用时自动建表 + 索引
- **表结构**：
  - `token_records`（id, model, provider, agent, input_tokens, output_tokens, cache_read, cache_write, status, latency_ms, ttft_ms, virtual_key_id, user_agent, session_id, request_model, remote_instance_uid, created_at）：**`model` 列 = 发往 upstream 的真实 model 名**（命名路由场景 = 目标真实名）；`request_model` = 客户端原始请求名（虚拟名路由场景可追溯，仅展示不参与定价）；**`agent` 列 = 来源 key 名（本地 vk 名 / 远程 `remote/{instance}/{vk名}`），Dashboard Agent 维度展示由 `user_agent` 查询时派生（见 `docs/agents/data-conventions.md`「Agent 维度派生」），历史 agent 列值仅存 Key 列展示**；`user_agent` = 客户端 UA（派生 agent 的数据源，可 NULL）；`session_id` = 会话 id（**客户端原生 header 原值优先**：依次尝试 `x-claude-code-session-id` → `x-opencode-session` → `session-id` → `x-session-id` → `session_id` → `x-session-affinity` → `x-conversation-id`，取首个 trim 后非空值，截断 256；**未携带时回退网关会话指纹**（`buildSessionId`，与 session 粘性共用请求级解析结果，sha256 64 hex，仅当 body 带非空 `messages` 数组时回退——gemini `contents` / 非 chat 端点指纹退化为常量，留 NULL）；Records 表展示（`font-mono` 单列，桌面端 `max-w-[140px]` 截断 + title 全文，移动端 `break-all` 换行；无筛选/索引），sync 透传）；`latency_ms` = 整请求耗时（全部请求）；`ttft_ms` = 流式首 token 延迟（首 chunk 到达 - 请求开始，仅流式有值，非流式 NULL）；`remote_instance_uid` = 来源实例稳定身份键（NULL = 本地记录；非 NULL = ingest 推送来源，索引 `idx_token_records_remote_instance_uid_created_at`；存量 remote 行不回填）
  - `upstreams`（id, name, protocol, base_url, enabled_models(JSON), priority, enabled, health_check_model, health_status, health_updated_at, balance, balance_updated_at, balance_fetch_mode（`TEXT NOT NULL DEFAULT 'auto'`，存量迁移同默认；取值语义见 `docs/agents/gateway.md`），proxy_url_encrypted, header_transforms, probe_config, classifier_models, created_at）：`proxy_url_encrypted` = 可选 HTTP(S) CONNECT 代理 URL（AES-256-GCM 加密，可含 `user:pass@` 凭据，NULL = 直连；写后不可读，API 只回显脱敏 host）；`probe_config` = 自定义探活端点 JSON（`{path, body}`，NULL = 默认 chat → responses 双风格，详见 `docs/agents/gateway.md`）；`classifier_models` = 分类器模型声明 JSON（`[{model, type, maxInputTokens?, path?}]`，声明该 upstream 可作命名路由分类器的模型，NULL = 无；type 决定 wire format、upstream.protocol 决定认证/传输，详见 `docs/agents/gateway.md` 命名路由节）；`header_transforms` = 出站 header 变换 JSON（`HeaderTransform[]`，最后一棒：客户端透传 → accept-encoding → 注入 key → transforms；fill=缺失补/override=覆盖，值模板支持 `${var.sessionId|model|keyName|upstream}`，sessionId 复用请求级解析结果（原生 header 优先，否则为消息指纹）；**探测路径同样应用 transforms**——test-model/test-all-models/自动探活用固定基线头（`user-agent: token-tracker-probe/1.0`、accept/content-type 为 `application/json`、`accept-encoding: identity`，避免 undici 默认 `user-agent: node` 被边缘 WAF 拦）+ 注入 key + transforms，`${var.sessionId}` 取临时值 `probe-<8hex>`（单次探测内恒定）、`${var.keyName}` 占位 `probe`）
  - `upstream_keys`（id, upstream_id, api_key_encrypted, enabled, last_status, created_at）
  - `upstream_model_health`（upstream_id+model 复合主键, status, expires_at, updated_at）：model 级不可用标记（持久化）
  - `virtual_keys`（id, name, api_key_encrypted, enabled, comment, enabled_models(JSON, 默认 '["*"]'), max_rpm, max_tpm, max_daily_tokens, max_monthly_tokens, last_used_at, created_at）：后 4 列为配额上限（NULL = 不限）
  - `named_routes`（id, name, protocol, instruction, classifier_upstream_id, classifier_model, classifier_kind, enabled, created_at）：**命名路由**（客户端虚拟名 + 可选分类器），`UNIQUE(name, protocol)`；`classifier_kind` = `'priority'`（缺省，规则分类器：按优先级+可用性选链首，零 LLM 开销，此时 upstream_id/model 为占位 0/''）| `'model'`（LLM 分类器，指向须在 `upstreams.classifier_models` 声明，不加外键：删 classifier upstream 不 nuking 配置，运行时回退 priority 链首）。同名自动路由完全失效（详见 `docs/agents/gateway.md` 命名路由节）
  - `named_route_targets`（id, named_route_id, upstream_id, upstream_model, description, priority, created_at）：命名路由的目标池（分类器选项 + failover 链），`UNIQUE(named_route_id, upstream_id, upstream_model)`，`ON DELETE CASCADE` 随路由/upstream 删除；目标 upstream 协议必须与路由协议一致（admin API 写入时校验）；`description` = 目标特性说明（给分类器看）；**`upstream_id` 可空（NULL = 无 provider 目标）**：`upstream_model` 按路由解析（命名路由嵌套 > 自动路由候选池，详见 gateway.md），SQLite UNIQUE 对 NULL 不去重，auto 目标查重走 admin API 应用层 409
  - `admin_audit_logs`（id, action, actor, target_type, target_id, ip, user_agent, details, created_at）：管理操作审计日志（含网关 user-agent 记录）
  - `model_prices`（model PRIMARY KEY, input_price, output_price, cache_read_price(NULL→回退 input), cache_write_price(NULL→回退 input), source('models.dev'|'github'|'manual'), models_dev_id, updated_at）：官方价参考（USD/1M），**查询时计算**，record 不存价格；`model` = 发往 upstream 的真实名
  - `settings`（key TEXT PRIMARY KEY, value TEXT）：`admin_api_key`（AES-256-GCM 加密）、`totp_secret`、`totp_enabled`、`token_epoch`、`hidden_providers`（明文）、`session_token_ttl_hours`（明文）、`stream_idle_timeout_minutes`（明文，Security tab 编辑）、`model_aliases`（明文 JSON：`[{name, aliases[]}]` 归一化配置，Display pane 编辑）、`agent_aliases`（明文 JSON：`[{name, aliases[]}]` Agent 维度手动映射：UA 首段 token 精确匹配 aliases（大小写不敏感）→ 归属 name；Display pane 编辑，写入时 `invalidateQueryCache()`（派生结果变化无 DB 写入）、`hidden_sources`（**已废弃的遗留行**：Hidden Sources 功能已删除，代码不读不写；存量行的历史名单保留在库里，仅作人工查阅，不影响任何统计口径）、`models_dev_source`（明文，快照数据源开关 `"models.dev"|"github"`，Models 面板切换；非法值回退默认，无 env fallback）、`records_columns`（明文 JSON：`["date","session",...]` Records 表可见列 id 数组，Records 页 Columns 下拉编辑；**只存可见集合**，展示顺序恒按 `src/lib/records-columns.ts` 定义序；空数组/未知 id/坏 JSON 读取回退全列）、`audit_columns`（明文 JSON：`["time","action",...]` 审计日志表可见列 id 数组，Admin / Audit 页 Columns 下拉编辑；归一规则同上，定义在 `src/lib/audit-columns.ts`，校验/归一与 records_columns 共用 `src/lib/columns.ts`）、`totp_fail_count`（明文，TOTP 失败计数）、`totp_locked_until`（明文，TOTP 锁定截止时间戳）、`totp_last_counter`（明文 JSON `{secretHash, counter}`：最近一次验证成功的 TOTP 时间步，重放防护——同一 secret 只接受 counter 严格递增的码；换绑后 secretHash 变化即重新起算）、`recovery_codes`（明文 JSON：`{hashes:[sha256...], used:[bool...]}`，只存哈希不存明文）、`recovery_code_login_reminder`（明文，recovery code 登录提醒标记）、`sync_target_url`（明文，A 端 ingest URL）、`sync_token_encrypted`（AES-256-GCM 加密，ingest token）、`sync_instance`（明文 `[a-z0-9-]{1,32}`，**纯展示名**，随时可改，默认主机名回退 `b-xxxxxxxx`）、`sync_instance_uid`（明文 `u-[a-f0-9]{32}`，**稳定身份键**：首次生成持久不变、不可编辑、reset 不重置）、`sync_epoch`（明文，DB 初始化时生成持久不变）、`sync_cursor`（明文数字，已确认推送的最大 record id）、`sync_bound_uid`（明文，A 端确认的绑定实例 uid）、`sync_dropped_count`（明文数字，累计 drop 记录数）、`sync_last_success_at` / `sync_last_attempt_at`（明文 ISO）、`sync_last_error`（明文 JSON `{type, message, firstFailedAt}`，B 端推送状态可观测）
- **responses 归属表**：`response_bindings`（response_id TEXT PRIMARY KEY, virtual_key_id INTEGER, created_at）：`POST /v1/responses` 成功后从响应里取顶层 `id` 记归属，`/v1/responses/{id}` 子路径透传前比对——映射存在且 vk 不一致 → 403，无映射（升级前存量 id）放行；写入时顺带删除 30 天前旧行（best-effort，幂等）
- **多实例同步新表**：`ingest_tokens`（id, name, api_key_encrypted(AES-256-GCM), bound_uid(TOFU 绑定 uid), enabled, last_used_at, created_at）、`sync_instances`（uid PRIMARY KEY, instance_name(展示名，每次推送刷新), epoch, last_record_id 去重水位, updated_at）。**uid = 身份键（TOFU/水位/级联删除），instance_name = 展示名（改名安全、重名无害）**
- **relay（sub node）相关表与补列**（详见 `docs/agents/relay.md`）：
  - `devices`（id, fingerprint UNIQUE(`u-<32hex>`), name, public_key(X25519 SPKI DER base64url), token_hash UNIQUE(**只存 sha256**，NULL = 已登记未授权), created_at, last_seen_at, revoked_at）：索引 `idx_devices_revoked`。因为只存哈希，设备列表**不提供 token 前缀**（设计决定，不加前缀列）
  - `device_pairings`（code_hash PRIMARY KEY(**只存 sha256**，码本身不落库), client_secret_hash, fingerprint, name, public_key, client_ip, user_agent, status(`pending`/`authorized`/`denied`/`expired`), poll_count, created_at(ISO), expires_at(**INTEGER epoch ms**, 600s), consumed_at）：索引 `idx_device_pairings_expires`
  - `device_plans`（plan_id PRIMARY KEY, device_id, virtual_key_id, hops_json(`[{hopIndex, upstreamId, keyId, realModel}]`), mode, protocol, request_model, user_agent, session_id, record_session_id, reserved_tokens, reserved_rpm, created_at(ISO), expires_at(**INTEGER epoch ms**, 10min), reported_at, status）：索引 `idx_device_plans_expires` / `idx_device_plans_vk` / `idx_device_plans_device`。**写库素材以这里为准**（report 只回 `hopIndex`）；`reported_at` 幂等；未上报过期 → 清扫并计 `relay_gap_count`
  - `device_latency_buckets`（device_id, kind(`plan`/`report`), bucket_start(**epoch ms，整分钟对齐**), count, sum_ms, max_ms, last_ms）：**复合主键 (device_id, kind, bucket_start)** + 索引 `idx_device_latency_buckets_start`。relay 自测的 relay⇄center RTT 分钟桶：relay 侧已聚合完（每桶只发 5 个数字，不发原始样本），中心 `ON CONFLICT DO UPDATE` 覆盖写 → report 重试重传幂等。5h 窗口 = 300 桶/kind，出窗口的行由 `maybeSweep`（60s 节流）删除。展示口径：`latestMs` = 最近一个有样本桶的 `last_ms`、`avgMs` = 5h 加权 Σsum/Σcount、`maxMs` = 5h 内 MAX(max_ms)
  - `token_records.device_id`（NULL = 本机直连或 sync 推送；非 NULL = relay 来源；索引 `idx_token_records_device_created_at`）+ `virtual_keys.key_fingerprint`（vkFp = `sha256("vkfp:v1:"+明文)` hex，唯一索引，**只做认证索引、不参与 session 指纹**）。注意：`upstream_keys.device_id`（per-device key）已移除，存量列由 `migrateDropUpstreamKeyDeviceId()` 幂等 DROP
  - **vkFp 回填**：`backfillVirtualKeyFingerprints()`（initDatabase 末尾，幂等，只处理 `key_fingerprint IS NULL`）：`GATEWAY_SECRET` 缺失 → 跳过；单行解密失败保持 NULL（继续走全表解密回退）。`resolveVirtualKey()` 读取顺序 = 指纹索引命中 + `safeCompare` 复核 → 回退全表解密比对（指纹只索引不作为放行依据）
- **存量迁移**：`migrateColumns()` 泛化支持多表（token_records / virtual_keys / upstreams），通过 `PRAGMA table_info` 检测缺失列并 `ALTER TABLE` 补列（`CREATE TABLE IF NOT EXISTS` 不会补列）；`migrateTokenRecordsModelColumns()` 专用一次性迁移：`request_model` 回填 = model、`model` 覆盖 = `target_model`（旧 schema）、DROP `target_model`（幂等）；`migrateSyncInstancesTable()` / `migrateIngestTokensTable()` 同步表重建迁移（幂等）：sync_instances 缺 `uid` 列 → 重建为 uid 主键（**旧行丢弃**，协议已破坏必然重绑重推）；ingest_tokens 存在 `bound_instance` 列 → 重建为 `bound_uid`（**token 行全量回迁**，用户资产不可丢弃，仅 bound_uid 置 NULL 等待重新 TOFU 绑定）；`migrateNamedRoutesTables()` 命名路由迁移（幂等）：旧 `routing_rules` 行 → `named_routes(classifier_kind='priority')` + 各目标一条 `named_route_targets`（priority 缺列时回填 0）；旧 `virtual_models` 行 → 同名同协议 upsert（分类器配置以 vm 为准）+ `virtual_model_routes` 目标回迁，随后 DROP 三张旧表；旧表不存在（全新库/已迁移）直接跳过；`migrateNamedRouteTargetsNullableUpstream()`（幂等）：`named_route_targets.upstream_id` 放宽可空（PRAGMA `notnull` 检测，NOT NULL 存量表重建回迁）；`migrateDropUpstreamKeyDeviceId()`（幂等）：`upstream_keys.device_id`（per-device key）已废弃 → PRAGMA 检测后 `DROP COLUMN`。**升级含义**：存量 `device_id` 非空的 key 会变成通用 key（直连/探活/分类器/所有 relay 共用），不再有「仅该 relay 可见」的隔离 —— 想保持隔离请换独立 upstream 或升级前手动删除这些 key
